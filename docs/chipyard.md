# Assemble a digital SoC in Chipyard

[简体中文](chipyard.zh-CN.md)

This example builds a public, generic one-Rocket system, not a physical board. Complete [component generation](build.md) and [native simulation](simulation.md) first. Platform compilation uses Scala 2.13.12, Chisel 6.5.0, chiseltest 6.0.0 and ScalaTest 3.2.19. Product SV remains generated by Chisel 7. Use firtool 1.75.0 for system lowering, separately from the component's 1.149.0 tool.

## 1. Pin upstream and initialize its environment

Start beside the `jpeg-xl/` clone with a new `chipyard/` directory:

```sh
git clone https://github.com/ucb-bar/chipyard.git
git -C chipyard checkout --detach 69eba860a352343e4ac6b6df0f3638a79a86ec78
cd chipyard
./build-setup.sh riscv-tools
source env.sh
git rev-parse HEAD
git submodule status --recursive
sbt 'show sbtVersion'
firtool --version
```

Install the host-package/Conda prerequisites documented by this [pinned upstream](https://github.com/ucb-bar/chipyard/tree/69eba860a352343e4ac6b6df0f3638a79a86ec78). Setup downloads substantial public dependencies and initializes submodules. Record the gitlink versions instead of substituting a floating Rocket checkout. Initialized matching submodule lines must not start with `-` or `+`. Java and the RISC-V toolchain must be on the current shell PATH.

## 2. Install separate source projects

Return to the `jpeg-xl/` root:

```sh
cd ../jpeg-xl
python3 tools/install_chipyard.py --chipyard ../chipyard
```

The installer checks upstream HEAD, copies `integration/`, `examples/` and `rtl/` into `chipyard/generators/jpegxl/`, and installs `integration/chipyard/jpegxl.sbt` at the Chipyard root. It refuses an existing destination. It does **not** copy the component `build.mill` or Chisel 7 sources into Chipyard. Added projects are:

- `jpegxlPlatform`, depending on `rocketchip`, for CSR/DMA, `JxlKey` and `CanHaveJxl`.
- `jpegxlSoc`, depending on `chipyard` and `jpegxlPlatform`, for `examples/chipyard/.../JxlRocketConfig.scala`.

`JxlExampleSystem extends chipyard.DigitalTop with CanHaveJxl` is the actual attachment point. `WithJxlExampleSystem` selects `chipyard.BuildSystem`, `WithJxl` enables `JxlKey`, and `JxlRocketConfig` selects one Rocket. Enabling the key without mixing the trait into a system instantiates no encoder.

## 3. Test adapters and configuration

Use Verilator **5.022** for these chiseltest 6 tests, from the pinned upstream environment; the standalone Chisel 7 component scripts use 5.050. Check `which verilator` and `verilator --version` after sourcing Chipyard's environment. Do not mix a relocated executable with another installation's `VERILATOR_ROOT`. In particular, 5.050's removed global `WData` typedef breaks this older JNI harness; this is a test-tool mismatch, not an RTL failure. Keep the two environments separate.

Run in `chipyard/`:

```sh
cd ../chipyard
sbt 'jpegxlPlatform/testOnly jpegxl.platform.JxlCsrSpec jpegxl.platform.JxlDmaSpec'
sbt 'jpegxlSoc/compile' 'jpegxlSoc/runMain jpegxl.example.CheckJxlRocketConfig'
```

Tests execute CSR/DMA RTL in Verilator. Synthetic result stimulus in the CSR test is not a codec. Require all ScalaTests and `JXL_EXAMPLE_CONFIG_PASS cores=1 sbus_bits=128 mbus_bits=512`. This is not whole-SoC software execution.

## 4. Wires, buses, memory and interrupts

`CanHaveJxl` makes these connections:

| Interface | Connection and requirement |
| --- | --- |
| CSR | 128-bit SBUS through width/fragment/buffer adapters to a 32-bit manager, 4 KiB at `0x10040000` |
| DMA | Native 512-bit memory through `JxlDmaBridge`, width/buffer adapters to coherent SBUS; read sources 0–15, writes 16–31 |
| Clock | `encoder.clockNode := sbus.fixedClockNode`; no asynchronous crossing in this example |
| Reset | Domain reset becomes active-low native `rst_n`; system rules must handle outstanding DMA during reset |
| Interrupt | `ibus.fromSync := encoder.intNode` to PLIC; obtain its number from generated DTS |
| Memory | `[0x80000000,0x180000000)`, 4 GiB; 512-bit internal MBUS, width-converted to 64-bit external AXI for upstream SimDRAM |

The bridge's DDR filter is hardcoded, not a `JxlParams` field. A different window requires coordinated changes to DMA filtering, software `jxl_region`, linker/allocation and tests—not just DTS. Native 33-bit addressing does not remove platform restrictions. Preserve coherent 64-byte Get/Put support.

## 5. Generate FIRRTL, device tree and SV

Build upstream BootROM with cross-GCC/objcopy on PATH. Use fresh outputs; the ROM must also be in the generator's target directory for relative lookup:

```sh
make -C generators/testchipip/bootrom bootrom.rv64.img \
  GCC=riscv64-unknown-elf-gcc OBJCOPY=riscv64-unknown-elf-objcopy
mkdir -p build/jxl-example/generated
cp generators/testchipip/bootrom/bootrom.rv64.img build/jxl-example/generated/
sbt 'jpegxlSoc/runMain chipyard.Generator --target-dir build/jxl-example/generated --top-module chipyard.harness.TestHarness --configs jpegxl.example.JxlRocketConfig --name JxlExample'
firtool --format=fir --verify-each=true --warn-on-unprocessed-annotations \
  --disable-annotation-classless --disable-annotation-unknown \
  --lowering-options=noAlwaysComb,disallowLocalVariables \
  --annotation-file=build/jxl-example/generated/JxlExample.anno.json \
  --split-verilog -o build/jxl-example/rtl \
  build/jxl-example/generated/JxlExample.fir
```

Expect `JxlExample.fir`, `.anno.json`, `.dts` and system SV. Check `jpegxl@10040000`, compatible `openrtl,jpegxl-fast-v1`, `reg`, `interrupts`, 4 GiB memory and one CPU in DTS. The supplied configuration generated interrupt 2 in our check, not the benchmark simulation branch's hardcoded 5; inspect your own DTS. Search emitted SV for `FastNativeEncoder core` in the encoder clock domain (a LazyModule need not retain its Scala class as a module filename), with no duplicate implementation.

## 6. Resolve the BlackBox implementation

`JxlNativeBlackBox` declares ports; it does **not** automatically add product SV to SBT/firtool output. From the Chipyard root run the helper in the original JPEG XL clone:

```sh
python3 ../jpeg-xl/tools/make_soc_filelist.py \
  --soc-rtl build/jxl-example/rtl \
  --native-rtl generators/jpegxl/rtl/native \
  --out build/jxl-example/combined.f
```

The installer copies digital source sets, not helper scripts. This list explicitly includes native product/assertion layers and include directories, plus system-emitted/resource SV. The helper rejects duplicate module files and checks critical modules. Do not resolve an undefined BlackBox with a stub. Select the stage-2 output with `--native-rtl` to use freshly emitted product SV, without adding a second product set or using a verification top for synthesis.

Whole-SoC simulation additionally needs upstream TestHarness DPI, memory/clock models and FESVR libraries. The list is an RTL input, not a complete C++ link command. A plain `verilator -f combined.f` does not produce an executable SoC. Follow upstream `sims/verilator` Makefile, register SBT project `jpegxlSoc` and config `jpegxl.example.JxlRocketConfig`, and add the product inputs from `combined.f`. The `JXL_SOC_SIM` branch of `software/jxl_benchmark.c` supports HTIF signatures but does not replace boot/memory-loading adaptation.

For the upstream Make flow, generate a **native-only** external list; Make itself supplies system files, so do not pass `combined.f` a second time. From `jpeg-xl/`, then `chipyard/`:

```sh
python3 tools/make_soc_filelist.py --native-rtl rtl/native --out build/jxl-native.f
cd ../chipyard
JXL_NATIVE_FILELIST=$(realpath ../jpeg-xl/build/jxl-native.f)
make -C sims/verilator -j2 SBT_PROJECT=jpegxlSoc GENERATOR_PACKAGE=chipyard \
  CONFIG_PACKAGE=jpegxl.example CONFIG=JxlRocketConfig \
  EXT_FILELISTS="$JXL_NATIVE_FILELIST"
```

This optional command builds an upstream simulator, not a board image. To execute software, first port the [ELF](driver.md) to this generated DTS/PLIC and boot environment, build with `JXL_SOC_SIM`, then invoke the same Make command with `run-binary-fast BINARY=<your-ELF> LOADMEM=1`. Replace `<your-ELF>` with the actual absolute path, and do not type the placeholder literally. Inspect HTIF exit/signature and complete-file checks, not only successful simulator compilation. This whole-SoC execution is a separate qualification step; the native and adapter tests do not establish it.

## 7. Port to your platform

Keep `CanHaveJxl` and the compiler-project boundaries when mixing into your `BaseSubsystem` subclass or extending this example. Recheck address collisions, coherency, DDR ranges, reset, PLIC allocation and boot. Start with the [polling driver](driver.md), then test interrupts. Vendor DDR controllers, physical IO/clock constraints, synthesis, implementation and programming belong to your platform project, not this board-anonymous example.
